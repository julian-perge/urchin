# Fix the original's bugs and keep its quirks

[#1](https://github.com/julian-perge/urchin/issues/1) keeps behavior faithful to the original and asks for an ADR for any departure a player could notice. This ADR covers one kind of departure for every case at once: the port fixes an Original bug and keeps a Quirk. An Original bug is code in the original that cannot do what it evidently means, such as a variable that is stale or missing in that scope, an accidental repeat, or a flag set on the wrong object. A Quirk is odd behavior that follows consistently from the original's rules, however unexpected. Reproducing an Original bug would mean carrying the original's stale state into the port, which nobody wants to build or test, while dropping a Quirk changes a rule the original really has. The project owner drew this line while grilling [#144](https://github.com/julian-perge/urchin/issues/144).

A fix that cites this ADR adds its case to the first list below instead of writing its own ADR. A Quirk found along the way goes on the second list, so it can be readdressed later if keeping it turns out to be the wrong call. A case whose fix hasn't landed yet ends with the issue that lands it.

AS paths below are relative to `dev/source_files/action_script/`. The conductor is `frame_217/PlaceObject2_3389_480/CLIPACTIONRECORD onClipEvent(enterFrame).as`.

## Original bugs the port fixes

- When a shield soaks a whole Buff tick, `buffTicker` plays the Shield clip through `IDKT` (`frame_42/DoAction_10.as:72`), a global that `executeMove` last set to whichever unit the last move hit. The port plays the Shield clip on the unit whose shield soaked the tick.
- `executeMove` draws the Floating number of every damage result twice (`frame_42/DoAction_8.as:80` and `84`), and under sswitch it stacks a heal-green number over the element-colored one (80 and 137). The port draws one Floating number per result, in the color the original leaves on top. The original's only visible trace is a doubled highlight.
- `executeMove` flashes its target through `_root.BATTLEFLASH`, one clip for the whole battle that each call points at its own target (`frame_42/DoAction_8.as:95-99`), so a move that hits several units flashes only the last one. The port flashes every unit a result lands on, because each Fighter presenter has its own Result flash.
- The death voice and the bar's fade play inside `lifeBarUpdate` (`frame_42/DoAction_8.as:345-347`), which does nothing when the bar's rounded percent hasn't changed. So a unit killed from under 0.5% life dies with no voice and its bar never fades. The port plays the death voice and the fade on every death. Lands with [#148](https://github.com/julian-perge/urchin/issues/148).
- The AI reads `focusCheck`, `playerFocusCheck`, `focusMove` and `D_Array_*` left over from the previous caller (section 2.11 of `docs/research/2026-11-07-original-logic-vs-port.md`). The port computes them for each caller.
- On the cost-failure path, a Buff tick may re-raise the impact flag on `_root` instead of on the conductor's clip, so the impact block could run the unpaid move with a stale `strikeSuccess` (conductor:475-531, open question 4 of the same research doc). Nobody has seen this in the running game. The port never runs a move whose cost failed.
- `krinBoltMake` puts bolt N at depth `600 + N` and its trail at `500 + N` (`frame_42/DoAction_4.as:140` and 176), and `boltMakerCounter` is reset only when that frame's code first runs (line 221), not for each battle. Floating numbers use depths 1620 to 1639 (`frame_42/DoAction_7.as:4`). So the session's bolts 1020 to 1039, and the trails of bolts 1120 to 1139, can replace a live Floating number, and every later bolt draws over the numbers. Nobody has seen this in the running game. The port always draws Floating numbers over bolts.
- `krinMelee` takes the fighter clip's position when the swing starts as the fighter's home (`boltx`, `frame_42/DoAction_4.as:38-39`), and its Runback ends by putting the clip there (119-120). The next action dispatches before a Runback ends, so a fighter that swings again while it is still running home, such as the last fighter of a Half-turn whose team also acts next, ends up short of its slot for the rest of the battle. The port keeps each fighter's own home and runs the Runback to it, and the dash still starts from where the fighter stands, as the original's does. Lands with [#175](https://github.com/julian-perge/urchin/issues/175).
- GridZoomer's last step puts BATTLESCREEN's `_x` and `_y` back where it rests and leaves its scale to come back by itself (`DefineSprite_3419/frame_4/DoAction.as:27-36`). A zoom that starts before the last one has ended, as the next move's can while a Melee move's zoom steps out, ends on the scale the first was cut off at, and the screen stays zoomed for the rest of the battle. The port puts the scale back too. Lands with [#176](https://github.com/julian-perge/urchin/issues/176).
- `checkIfAllStar` scans the live game through `Krin.data.Class`, which nothing assigns (`frame_42/DoAction_20.as:34-44`), so the live game counts toward All Star only once it is saved. The port counts the live game on the winning battle, with the four slot saves. Lands with [#42](https://github.com/julian-perge/urchin/issues/42).

## Quirks the port keeps

- A shield exactly as big as a hit is not a Shield block. The shield drops to 0, and the hit plays its flash, its `hit` label and the hit voice with no number (`frame_42/DoAction_8.as:70-131`).
- A shield exactly as big as a Buff tick's total does not soak the whole tick either. `buffTicker` takes that branch only for a shield that is strictly bigger (`frame_42/DoAction_10.as:64-73`). The shield drops to 0, and the tick draws no number, plays no Shield clip and does not hold the next action back, because its total is 0 (85 and 99).
- Any rise in a unit's stun replays its stun animation, even on a unit that is already stunned, and any fall plays `outofstun`, even one that leaves it stunned (`applyChangesKrin`, `frame_42/DoAction_10.as:468-481`).
- `dressChar` draws a `MODEL5` unit at 0.8x and 10 px lower.
- A Floating number between 0 and 1 plays its label with no digits. `KrinNumberShow` draws any number above 0, and its digit loop drops the fraction (`frame_42/DoAction_7.as:8` and 27-61).
- `KrinNumberShow` cycles its Floating numbers over 20 depths, 1620 to 1639, so a 21st number replaces the one still at its depth (`frame_42/DoAction_7.as:4`, 37 and 75-79).
